# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

kloudlite — a terminal agent harness for cloud dev environments. Bun + Turborepo monorepo:

- `apps/tui` — the TUI (opentui/React), plus an SSH server that serves it
- `packages/agent` — wrapper over the pi SDK (`@earendil-works/pi-*`): models, auth, sessions
- `packages/tools` — provider-agnostic tool registry (`ToolDef`/`Registry`); ships **no** built-in tools

## Commands

```bash
bun install
bun run dev                    # turbo dev → apps/tui local TUI
bun run --cwd apps/tui dev     # same, directly
bun run serve                  # SSH server on :2222 (ssh -p 2222 anyone@localhost)
bunx turbo check               # tsc --noEmit across all workspaces
bun test                       # from apps/tui — bun:test
bun test src/slash.test.ts     # single file
bun test -t "sidebar renders"  # single test by name
```

## Architecture

**Agent layer** (`packages/agent/src/index.ts`). A single module-level `ModelRuntime` owns every provider, the model catalog, and credentials. Config lives under `~/.config/kloudlite/` (override with `KLOUDLITE_CONFIG_DIR`): `auth.json`, `models.json`, `settings.json` (defaultModel/theme/sidebar/thinking), `sessions/<key>/`, `host_key.pem`. `createSession({key, ...})` continues the most recent persisted session for that key unless `fresh`; `/clear` archives files instead of deleting them. Custom tools from a `Registry` are adapted into pi tool defs here.

**Sessions are hierarchical and independent** (`apps/tui/src/sessions.ts`). The hierarchy is **working session › main session › workspaces**: **every context holds named sessions** — the environment's main sessions and each workspace's own. `sessionBase(wsId?)` gives the context (`main` or the workspace id) — **the environment is not part of a session key**, so connecting elsewhere never swaps a transcript and `sessionKey(...id)` hangs a session off it (`<base>` for the default "main", `<base>:<id>` for named ones); `app.tsx` tracks `sessionId[base]`. Workspaces hang off a main session (`Workspace.session`), so switching main sessions swaps which workspaces are in view. A session's **title is inherited from what owns it, never derived from a prompt or from context**: the main session is always `Working Session`, a workspace's session is the workspace name, and an ephemeral one is its own agent name. `/session name` still names a session in `meta.json` for `/session use`, but the title bar does not read it. Titles and descriptions live in each session dir's `meta.json` (`nameSession`/`describeSession`/`listSessions` in the agent package) and are driven by `/session name|desc|use`. **There is no `/session new`** — sessions are not created from the UI; `/session use` continues one that already exists, and a session comes into being by being used. Every chat session is topped by a **title bar** (`components/SessionTitle.tsx`): the inherited title in bold, a dim subtitle under it **only** when `/session desc` set one (there is no derived subtitle — the workspace-and-changed-files line was removed), `working` on the right while a turn streams, and a hairline below. Clicking it opens `/session`. The subtitle deliberately does *not* repeat the environment path. The **prompt card's bottom row names the session you are typing into** (`contextPath` in `app.tsx`, the `session` prop on `Prompt`) — `Working Session` at the main context, the workspace path (`api-gateway › load-test`) inside one, and it stays put in vim NORMAL, where the mode moves into the hint that follows it. It used to read `Orchestrator`/`Agent`: every session *is* an agent, so naming the agent said the same thing twice and never said which session. The **hint bar's left slot carries the connected environment** instead — the bottom row would otherwise repeat the name the card already shows. **Workspaces belong to the working session, not to an environment** (`MOCK_WORKSPACES`, `allWorkspaces` state in `app.tsx`) — an `Environment` carries only its services. So connecting elsewhere brings this exact list along and can never mix another session's or environment's workspaces in, and there is no move/attach verb: workspace actions are intercept, release and clone only. **One connected environment at a time** — no tabs, no open-env list: **The agent drives the lifecycle, not the user** — there is no actions menu and no `/env`, `/workspace`, `/intercept` or `/release` command; connecting, creating, cloning and intercepting are things the agent does. `connectEnv`/`newWorkspace`/`cloneWorkspace`/`interceptService`/`releaseInterception` survive in `app.tsx` as the shape those agent tools will call and are currently unreachable (marked `ponytail:`); the jump palette navigates workspaces only. Its services hang off it in the sidebar's Environment section. The sidebar (`components/Sidebar.tsx`) is modelled on a desktop-app layout and **docks on the right**. **Working session and environment are different things and are never mixed.** The header is the working session (`✦ Working Session`) and the `Workspaces` list under it belongs to it. The pinned bottom block is the environment: an `Environment` heading, the connected env's name, its services indented under it, and the restore point it is sitting on as the **last line of the block**, dim and labelled (`current snapshot: <name>`, from `Environment.snapshot`) — labelled because a bare name reads like a tag, and at the bottom because beside the env row it collides with a long env name; the agent takes and switches snapshots and the UI never lists them — Services belong to the environment, so they are **indented directly under it**. The services have no heading of their own; the indent is what says they are the env's. **Section headings are bold title-case followed by a hairline** that fills the rest of the row (`Heading` in `Sidebar.tsx`), the same separator the session title bar uses — no SHOUTING CAPS and no full-width rule above a heading, since the hairline already divides. **Every row is exactly one line** — a workspace's branch and change count are deliberately not shown (tried, too noisy); ephemeral workspaces appear by their own short `name` on `├`/`└` branches under their parent. Every agent is isolated by code, network and storage, and none of that surfaces in the sidebar. A service row keeps the accent on its own name when intercepted and puts `→ workspace` in the dim right-hand column ahead of `proto:port`, so ports stay aligned. No status dots or phase tags — rows are plain text; one state word (`working` while its session streams, `42%` cloning, an owner) sits on the right only when it matters. A turn keeps streaming in its own session while the user looks at another — never assume the visible session is the running one. `App` holds `SessionMap` state plus a `useRef` map of live `AgentSession` promises created lazily per key.

**UI** (`apps/tui/src/app.tsx`, ~1.1k lines — the whole keyboard/state machine). **Two key schemes, chosen by the `vim` setting** (`/settings vim on|off`, default **off**): with vim off the prompt is always live and the commands live on ctrl+<letter> (`^f` views, `^p` jump, `^q` queue, `^j`/`^k` cycle workspaces, `^1`-`^9` / `^0`, `?` help); with vim on the keyboard is modal — NORMAL takes those same commands as bare letters and `i` enters INSERT. Both share a `/` command overlay, a palette, and a Files review view. Agent events (`message_update`, `tool_execution_*`, `queue_update`, `compaction_*`, `auto_retry_*`) are translated into `Entry[]` for `Transcript`.

**Views**: `f` cycles chat › files › processes for the selected workspace (each view takes an `onCycle` prop so `f` works from inside it too). The files view holds both sections in one list — CHANGES (vs HEAD) above the FILES tree, reader pane on the right (`v` flips a changed file between its diff and its full contents — in the full view the line number goes green for a line added since HEAD and a red `── n deleted ──` rule marks where lines were removed, computed by `fullFile`/`marks` in `git.ts` from a `-U0` diff); the processes view (`components/Processes.tsx`) lists what the workspace runs and shows the selected process's output, same two-pane shape and keys. 

**Mouse works everywhere it makes sense**: opentui exposes `onMouseDown` on any `box`, so tabs, sidebar rows (environment + workspaces), slash-menu and ask/permission options, hint-bar hints, files-view tree rows, change headers and search hits are all clickable; wheel scrolling comes from the `scrollbox`es. Tests drive it with `mockMouse.click(x, y)`.

**Responsive rule, copied from opencode** (`routes/session/index.tsx`): one breakpoint, `wide = columns > 120`. The sidebar is 42 columns by default and **resizable** — `[` / `]` in vim NORMAL, or `/settings width wider|narrower|reset`, step 4, clamped to 28..64 and persisted as `sidebarWidth` in `settings.json`. opentui exposes no drag stream, so the divider itself can't be dragged (marked `ponytail:`). At every size — wide terminals dock it on the right of the session column; narrow ones show it only when opened (`/settings sidebar show`) and then as an absolute overlay (right-aligned) over a dimmed transcript. The hint bar drops secondary hints when not wide.

**Layout must match opencode (sst/opencode) 1:1** — paddings, borders and the prompt card are ported from its source (`src/ui/border.ts` holds the SplitBorder chars). When the UI looks off, diff against opencode's source, not against a screenshot.

**The tree is exactly three levels**: main session › workspaces › ephemeral workspaces (spun off a workspace like a git worktree, `parent` set). Nothing nests deeper — `parentFor()` re-parents an ephemeral's clone onto its workspace, and `depthOf()` returns 0 or 1. The list stays flat and in tree order so `focus` keeps indexing it 1..N; `treePrefixes`/`wsPath` derive the guide characters and the context path.

**Mock data**: `apps/tui/src/workspaces.ts` is entirely placeholder (environments, workspaces, services, `CURRENT_USER`). Nothing there reflects real kloudlite semantics; expect it to be replaced wholesale.

**Queued messages** (`components/Queue.tsx`). Prompting while a turn streams queues the text in pi (steering interrupts, follow-up waits). `Session.queued` holds the real `QueuedMessage[]` (`{text, kind}`), not just a count, fed by the `queue_update` event. A **QUEUED** panel above the prompt lists them (`steer`/`after` per row); `^q` (or `q` in vim NORMAL) targets the list (or click `N queued` in the hint bar), then `j`/`k` pick, `enter` pulls one back into the prompt to re-edit, `d` drops it, `esc` leaves. pi has no per-item removal, so `rewriteQueue` clears the queue and re-queues the keepers in order onto the queue each kind names.

**The wheel is accelerated** (`apps/tui/src/wheel.ts`). opentui's `scrollbox` defaults to `LinearScrollAccel` — one row per wheel tick, which makes a long transcript or file tree feel stuck — so every scrollbox (transcript, sidebar, both files panes, processes) passes `scrollAcceleration` from `useWheelAccel()`, opentui's `MacOSScrollAccel`: a slow gesture still steps one row, a fast burst ramps up. It is a **hook, not a module constant**. The accelerator holds a velocity window between ticks, so it has to survive re-renders — a per-render `new` resets the streak on every repaint — but it must not be shared either: the SSH server runs every client in one process, and one window fed by two people wheeling at once inflates both their multipliers.

**Transcript scrolling** (`components/Transcript.tsx`). opentui's `scrollbox` with `stickyScroll` pins the bottom while a turn streams; PageUp/PageDown page, `u`/`d` half-page in vim NORMAL. Scrolling away reveals a centred **↓ jump to bottom** row under the transcript — clickable, or `end` (`G` in vim NORMAL). Long blocks **collapse like Claude Code's**: an agent message or bash output over 10 **wrapped rows** renders its **first** 10 (the head, so it still reads from the beginning) above a dim `… +N lines  Click to expand` row (opencode's wording). That row stays once open, reading `Click to collapse`, so a block can always be put back. **Expanding is click-only** — opencode has no expand key and the old `ctrl+o` master switch (with its `openAll` XOR) is gone, so over SSH or with mouse reporting off nothing can be expanded; that is the accepted trade for one affordance instead of two. **The whole cell is the expander** — clicking anywhere in a collapsible block toggles it, since reaching the `… +N lines` row meant scrolling past the block first. The toggle fires on **mouseup at the mousedown position**, not on `isDragging`: opentui marks every up as dragging once a mousedown over selectable text has begun a selection, so that flag cannot tell a click from a drag. Hovering a collapsible cell tints it (`theme.surface`) and its `More` row brightens, so what is clickable says so. The scrollbox exposes no `onScroll`, so "am I at the bottom?" is sampled on a 200ms timer (marked `ponytail:`); that is also what catches wheel scrolling. A bash block's **command counts toward its rows too** (`shellRows` in `Transcript.tsx`): the `$ cmd` line wraps like any other text, so a `grep` over a lockfile is a dozen rows on its own — measuring only the output sized the box short and the output spilled past it, and the command is collapsed at the same width it is measured at. `collapse` counts **wrapped** rows, not `\n`s, which is why `Transcript` takes a `width` (`contentWidth` from `app.tsx`): model reasoning and bash output arrive as a few very long unbroken paragraphs, so counting source lines said 3 where the terminal drew 9 — the block was sized for 3 and the expander was drawn on top of the text.

**An empty transcript has two meanings** (`Session.restored` in `sessions.ts`, the `ready` prop on `Transcript`). A persisted transcript is read off disk when `createSession` resolves, so the first paint of a reloaded session has `entries: []` — and the welcome screen keyed off exactly that, flashing the wordmark over every session before its messages landed. `restoreTranscript` sets `restored` on both exits (and a failed open sets it too, or the screen stays blank forever); until then `Transcript` renders an empty box. Don't go back to `entries.length === 0` alone: "not loaded yet" and "nothing to show" look identical and only one of them is the home screen.

**Markdown is opentui's, not ours** (`Md` in `Transcript.tsx`). Agent messages and finished reasoning render through opentui's `<markdown>` renderable, so tables, lists, headings, blockquotes and fenced code all draw properly. The hand-rolled renderer it replaces understood `**bold**` and `` `code` `` and nothing else, so a table arrived as its raw pipes. `<markdown>` requires a `SyntaxStyle`, which allocates on the native side, so it is cached — but keyed on the palette's own colours, since `setTheme` mutates `theme` in place and a module-level constant would keep whichever theme loaded first. `streaming` is passed for the **last** entry only: it keeps the trailing block unstable so a half-written table row is not parsed as final, and settling the earlier entries lets their last token resolve. Collapsing markdown goes through **`collapseMd`, not `collapse`** — `collapse` rejoins soft-wrapped fragments with `\n`, which splits one table row across several lines and destroys the parse, so `collapseMd` cuts on *source* lines (screen rows still decide *whether* to cut) and closes an unterminated code fence in the kept head, which would otherwise swallow the rest of the block.

**Chrome is clicked, not read.** opentui starts a text selection on mousedown over any selectable renderable, and `selectable` defaults true — so clicking an expander, a hint, a sidebar row, a slash-menu option or a files/processes list row also swept a selection over its label. Every `text` inside a clickable row carries `selectable={false}`; the prompt's own value and the files/processes reader panes stay selectable, since that text is there to be copied.

**Slash commands** live in `slash.ts` (`commands` list + `menuItems(input, ctx)` producing option rows); handlers are in `app.tsx`. The overlay's draft **always carries its leading `/`** — `openCmd` prefixes it, `menuItems` is given it verbatim, and picking an option-command keeps it. Typing `/` into an empty live prompt opens the overlay via `changeInput` (the prompt owns the key), so the slash the user typed is the slash in the draft; stripping it anywhere desyncs `Input`'s internal copy of the value and keys get doubled or eaten. Deleting that `/` back out **closes** the overlay again (same `changeInput` branch) — the overlay must never outlive the slash that opened it, or the menu keeps filtering an input that is no longer a command.

**Pasted images** (`apps/tui/src/clipboard.ts`). `ctrl+v` reads a PNG off the system clipboard into the `images` state; an attachment is **a token in the prompt value, not a chip beside it** — opencode's model (`packages/app/src/components/prompt-input/attachments.ts` inserts the part at the cursor). `ctrl+v` is handled **inside `components/Input.tsx`**, which owns the caret: `onPasteImage()` keeps the image in `app.tsx` and hands back an `[Image N] ` token, `Input` inserts it at the caret and moves the cursor past it, so pastes keep their place and typing continues after them. `Input` renders any `[Image N]` run in the value as an amber badge (bold `theme.bg` on `theme.warning`). The counter is a `useRef`, not `images.length`, because a burst of keys in one stdin chunk runs every handler against the same render. On submit the transcript entry keeps the tokens where they were typed and carries an `images` count that draws a `File`/`clipboard` badge pair under it, the label reading `N Files` when more than one is attached; the model is sent the text **with the tokens left in** — they are how it tells one attachment from another, and stripping them left an image-only message with empty text. `ctrl+v` refuses with an error entry when the session's model does not list `image` in its `input` (pi's `Model.input`), since a text-only model drops attachments silently; an unresolved model does not block the paste. A token is **one thing to the caret**: backspace over an `[Image N]` deletes the whole badge in one press, and left/right step across it whole (`tokenStart`/`tokenEnd` in `Input.tsx`), since deleting it a character at a time leaves a broken `[Image ` on screen. `readClipboardImage()` is **per-platform and tries both**: macOS has no way to get PNG bytes out of `pbpaste`, so AppleScript coerces the clipboard to `«class PNGf»`, writes it to a temp file, and we read it back and delete it; Linux (and the bench browser terminal's stand-in) uses `xclip -t image/png`. It never throws — a missing tool or a text-only clipboard is a silent no-op, so don't "simplify" it down to one platform's tool.

**Provider login** (`apps/tui/src/components/Login.tsx`). One generic component drives every provider — pi owns the flow, we only render what it emits, so all 40 providers share these 170 lines and none of them is special-cased. It covers pi's four `AuthPrompt` types (`text`, `secret` masked, `select` with arrow keys, `manual_code`) and all four `AuthEvent` types (`info` with its optional `links`, `auth_url` — printed *and* opened with `open`/`xdg-open`, `device_code`, `progress`). **Both abort signals matter**: the flow-level one from `AuthInteraction`, and `AuthPrompt.signal`, which pi fires when something else answers a step — a `manual_code` prompt raced against the OAuth callback server. Without the per-prompt listener the user keeps typing into a prompt that already resolved.

**The model catalog is dynamic** (`refreshCatalog` in `apps/tui/src/models.ts`). All 40 providers implement pi's `refreshModels`; the per-provider JSON in `pi-ai/dist/providers/data/` is only an **offline seed**, and a seed goes stale — the bundled one is stamped 2026-08-07 and still lists `deepseek-v4-flash`, an id DeepSeek no longer serves, while missing `deepseek-flash`, the only DeepSeek model that accepts images. `models.refresh()` fetches each *configured* provider's live list (~500ms, errors returned rather than thrown, unconfigured providers skipped) and persists it, so the next launch starts correct. `app.tsx` holds the catalog in state seeded from the import-time list: the seed paints at once and the live list swaps in, so the network is never on the paint path. It refreshes at startup **and after a successful `/login`**, since a login configures a provider the first refresh skipped. Don't go back to a module-level `const catalog` — a never-refreshed catalog is pinned to whatever shipped in `dist`, which silently costs both model ids and capabilities.

**`/model` shows only models you can run** (`menuCtx` in `app.tsx`, `/model` branch in `slash.ts`). The catalog is 1300+ models across 40 providers, so models whose provider has no credentials are filtered out — they are unreachable, and picking one only fails at request time. What's left is **grouped by provider and sorted within it**, with the model's display name in the hint (the label is already `provider/id`). Filtering creates a first-run dead end, so two things cover it: a `/model` menu with nothing to show **offers the logins instead** (rows insert `/login <provider> <type>`), and a mount-time check appends `No AI provider connected yet — run /login to connect one.` to the transcript when no provider resolves, since typing `/login` is not discoverable. Both matter — the notice is the one a first-run user actually sees. Note `auth.ok` means *a credential resolved*, not that it works: a dead key still reads as connected until a request fails.

**`DEFAULT_MODEL` trusts what was saved** (`models.ts`). It is computed at import, *before* the refresh, so the only models it can see are the seed's — validating a saved `defaultModel` against the catalog there discarded any model the seed predates, and a cold start silently replaced a saved `deepseek-flash` with the anthropic fallback. A saved choice is now returned unvalidated; a model the provider has since dropped surfaces as a request error, which beats losing the user's choice. `modelLabel` already falls back to the bare id for a model the catalog doesn't know.

**Permission modes** (`PERM_MODES` in `app.tsx`, the gate at `installPermissionGate`). pi 1.0.4 has no permission system of its own — only `ToolAnnotations` hints — so the four Claude Code modes are ours, layered on the same `beforeToolCall` chain: `default` asks for everything in `GATED`, `acceptEdits` waves `write`/`edit` through but still asks for `bash`/`web_fetch`, `plan` **blocks** every gated tool with a reason telling the model to research instead (an answer the model can work around beats a card the user rejects every turn), `bypass` asks nothing. **Shift+tab cycles the mode** in both key schemes, so plain tab now only cycles workspaces *forward* — `k`/`^k` is the way back. The hook is installed once per session but the mode changes under it, so the gate reads `modeRef.current` rather than a captured value. The mode is **per-process and resets on restart**: a forgotten `bypass` persisted across launches is the one failure worth not having, which is also why there is no `/settings` row for it. `HintBar` shows it only when it is not `default` (`bypass` in `theme.error`), so the ordinary case stays quiet.

**Thinking is two separate settings** (`prefs` in `app.tsx`, `Settings` in `packages/agent/src/index.ts`). `thinking: show|hide` is **visibility** of thinking blocks in the transcript; `thinkingLevel: off|minimal|low|medium|high|xhigh|max` is pi's **reasoning budget**, passed to `createAgentSession` and applied live with `setThinkingLevel`. They are different concerns that both want the word "thinking" — don't collapse them. A level change applies to **every live session**, not just the visible one, since a turn may be streaming elsewhere. `autoCompact: on|off` drives `setAutoCompactionEnabled` the same way. All three are rows in the existing `/settings` overlay, so none of this adds chrome. `/settings` is **two levels** (`slash.ts`): one row per setting, its current value in the hint, and picking one lists that setting's values. Listing every key/value pair at once ran past twenty rows and the nine `thinkingLevel` values buried everything else.

**Thinking renders in two states** (`Transcript.tsx`, `case "thinking"`). While a message streams the entry is a one-line **ticker showing its newest line**; once `message_end` sets `done` it becomes a dim italic `Thinking` label over the body, both **behind a left rail** (`border={["left"]}`) and collapsing at the same 10-row head. **Reasoning never goes through `<markdown>`**: the renderer's own heading and bold colours override the `fg` we pass, so a finished thinking block rendered as markdown was visually identical to an agent message — the rail and the flat dim italic text are what tell the two apart. The streaming ticker carries the same rail so the block does not shift sideways when it lands. The old renderer clipped every thinking entry to `split("\n")[0]` with `height={1}` forever, which made `show` and `hide` look nearly identical and made a 32k reasoning budget invisible. Don't go back to a fixed one-line thinking row. `restoreTranscript` in `app.tsx` rebuilds a reloaded session's entries from `agent.messages`, so it has to pick `thinking` blocks out of the assistant content alongside `text` and `toolCall` — it originally dropped them, and every reasoning block vanished the moment a session was reopened. A restored block is finished by definition, so it is pushed with `done: true`.

**The env lifecycle tools are the agent's hands** (`registry.add` block in `app.tsx`). CLAUDE.md's rule that the agent drives the lifecycle left `connectEnv`/`newWorkspace`/`cloneWorkspace`/`interceptService`/`releaseInterception` unreachable; `env_status`, `env_connect`, `env_intercept`, `env_release`, `workspace_create` and `workspace_clone` are what finally calls them. They are registered once, but the state they act on changes every render, so they go through an **`envApi` ref reassigned on each render** — a tool that closed over state directly would act on whatever was true when it was defined. The UI's own functions address things **by position** (`focus - 1`, an env index) and a model only has names, so the wrappers are name-addressed and an unknown name comes back with the list of valid ones. `env_status` exists because those names have to come from somewhere, and each tool returns a sentence rather than nothing, since the model's next turn has to know what the UI now shows.

**Custom tools take their params as pi's second argument** (`adaptTools` in `packages/agent/src/index.ts`). pi 1.0's signature is `execute(toolCallId, params, signal, onUpdate, ctx)`. The adapter originally read the first argument, so every custom tool was handed its *call id* and every declared parameter arrived `undefined` — `web_fetch` failed with `error: undefined is not an http(s) URL` on a call whose arguments were correct. The mapping is **exported rather than inline** so it can be tested without a session, model or network: `createSession` casts it through `as never` to satisfy pi's generic tool type, so **nothing at compile time guards this**, and `apps/tui/src/tool-args.test.ts` calls `execute("call_abc123", {...})` directly. Don't delete it.

**Prompting mid-turn steers; pi's `prompt()` refuses** (`submit` in `app.tsx`). A second `prompt()` while a turn streams throws `Agent is already processing. Specify streamingBehavior ('steer' or 'followUp')` — pi does **not** queue it for you. `submit` therefore picks `steer()` when the target session is busy, and the choice reads **that session's** `busy`, not the visible one's: a turn keeps streaming in its own session while the user looks at another, so `const streaming = getSession(sessions, key).busy`. The `queue_update` event then paints the QUEUED panel as usual.

**Web tools are ours, not pi's** (`packages/tools/src/web.ts`, registered in `cli.tsx`/`server.tsx`). pi 1.0 ships files and shell only — there is no web tool in it — so `web_fetch` and `web_search` live in the previously-empty registry. `web_fetch` strips HTML with a handful of regexes rather than a parser dependency (script/style first, since their contents are not text), passes JSON and plain text through verbatim, and truncates at `maxChars` so one page cannot eat the context window. It is **in `GATED`**: a fetch leaves the machine and its URL can come from text the model just read, so the permission card shows the URL. `web_search` tries each provider in `SEARCH` (Brave, Tavily) and takes the first whose env key is set; with no key it **returns the names of the keys it needs** rather than an empty result, which would read as "nothing found". Both time out at 20s — a hung host must not hang the turn.

**Codemode is on by default and fixed per session** (`createSession` in `packages/agent/src/index.ts`, `/settings codemode`). pi 1.0 ships codemode — the model writes a JavaScript script that calls the other tools, instead of one tool call per turn — but it is **an extension that is registered inactive**, so two separate things turn it on: `createCodemodeExtension({mode: "only"})` has to reach the session as an `extensionFactories` entry on a `DefaultResourceLoader`, *and* `codemode` has to be activated by name. It is **added on top of `getActiveToolNames()`**, never passed as `tools`: naming `tools` replaces pi's default allowlist, so hardcoding the four built-ins silently dropped every other default tool. **`mode` is what makes the model use it** (`"on"` | `"only"`, default `"on"`): under `"on"` the direct tools stay declared and codemode's description lists only tools *without* direct exposure — i.e. nothing — so it is opt-in with an empty menu and the model always picks `bash`. Under `"only"` pi hides the direct declarations and lists every callable tool in codemode's own description, so a script is the way to call them. The loadout is assembled per request by `prepareLoadout`, not at session build, which is why reading the stored description tells you nothing about `mode`. pi fixes the tool list when the session is built, so unlike `thinkingLevel` and `autoCompact` the setting **cannot be pushed into live sessions** — `/settings codemode on` says it applies to sessions started from now on rather than silently doing nothing. It defaults to **on** (`prefs` in `app.tsx`) — scripting the tool calls is the point of having it, and a setting nobody discovers is a setting nobody turns on. A codemode call renders as the **bash block with its script where the command goes** (`Transcript.tsx`), a hairline between the source and the script's output, and both counting toward the collapse head; `toolSummary` keeps the script's newlines instead of clipping it to one line the way a bash command is clipped. Only the script's own output comes back — nested tool calls run inside pi's pipeline and never reach the transcript, so a codemode turn shows one block where the old path showed one row per call.

**Compaction reports real numbers** (`compaction_end` in `app.tsx`). The event carries `aborted`, `errorMessage` and a `result` with `tokensBefore`/`estimatedTokensAfter`, so the transcript line reads `context compacted — 42,103 tokens → ~8,200` and an aborted or failed compaction says so instead of claiming success.

**Provider env vars** (`envKeysFor` in `packages/agent/src/index.ts`). pi exports no provider-to-env-var mapping, but every provider resolves credentials through `ctx.env(name)` — so passing a context that records the names and returns nothing reports exactly what that provider reads, in preference order. Don't go back to guessing `${ID}_API_KEY`: it was wrong for 13 of 40 providers (Bedrock takes AWS credentials, Hugging Face `HF_TOKEN`, github-copilot `COPILOT_GITHUB_TOKEN`), which strands a user at the moment they are already stuck. An OAuth-only provider returns `[]`, and the model picker shows no hint for it.

## Terminal keyboard gotcha

The user runs WezTerm with the kitty protocol off. opentui's native setup writes `CSI >4;1m` (modifyOtherKeys mode 1), which keeps ctrl+h/ctrl+j as legacy bytes indistinguishable from Backspace. Both `cli.tsx` and `server.tsx` therefore re-assert mode 2 *after* startup — `cli.tsx` via `writeSync(1, ...)` because opentui patches and buffers `process.stdout`. Don't "clean up" those writes. Verify key fixes by capturing raw bytes (`tmux pipe-pane`).

## Testing

`bunfig.toml` preloads `src/test-setup.ts`, which points `KLOUDLITE_CONFIG_DIR` at a temp dir — without it tests write named sessions and settings into the real `~/.config/kloudlite`. `apps/tui/src/app.test.tsx` mounts the real `App` with `testRender` from `@opentui/react/test-utils`: drive it with `mockInput.pressKey/typeText`, assert on `captureCharFrame()` text. `mount()` writes `vim: "on"` into the temp config by default, so tests start in NORMAL mode and its `insert()` helper presses `i`; `mount({vim: "off"})` exercises the shipped insert-only default, where typing reaches the prompt straight away.
