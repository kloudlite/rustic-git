# rustic-git codebase audit — 2026-08-25

Five independent auditors with no prior context on the codebase reviewed it in parallel:
security, architecture/correctness, the workspaces subsystem, performance, and web +
code quality. Findings below are deduplicated and ranked by severity. Where two
auditors reached the same conclusion independently it is marked **[confirmed ×2]**.

Audited at `5784019` on branch `restructure`.

## Executive summary

The git/registry core is in good shape — the auditors independently confirmed that the
load-bearing invariants in CLAUDE.md are actually upheld in code, with tests naming
them. No critical findings there.

The workspaces/environments subsystem is the newest code and carries essentially all
of the serious risk: **one critical remote host-compromise**, plus a cluster of
lease/scheduling defects that will surface as data ending up on the wrong node or jobs
running twice. Fix those before onboarding real users.

| Area | Critical | High | Medium |
|---|---|---|---|
| Workspaces / agent | 1 | 5 | 8 |
| Registry / storage / merge | 0 | 0 | 5 |
| Performance | 0 | 7 | 13 |
| Web app | 0 | 0 | 2 |

## 1. Critical — fix now

### C1. Container escape: unvalidated mount `folder` bind-mounts arbitrary host paths **[confirmed ×2]**

`crates/workspaces/src/api.rs:536` · `bins/agent/src/lib.rs:569` · `crates/workspaces/src/engine/compose.rs:41`

`Mount.folder` is user-supplied and validated only for non-emptiness. It is then passed
to `live.join("volumes").join(&m.folder)` and rendered as a docker-compose bind source.
`Path::join` discards the base when the joined component is absolute, and `..` traverses
out just as well.

Any authenticated user can create an environment with:

```json
{"folder": "/", "path": "/host"}
```

The agent — running as **root on the btrfs host** — then bind-mounts the host root
filesystem read-write into a container whose image the same user chose. That is
arbitrary host read/write: drop a key in `/root/.ssh`, edit `/etc`, done. `folder`
containing `:` also corrupts the compose volume string, and `m.path` is unvalidated
too (can append a second mapping or `:ro`-style options).

**Fix:** validate `folder` as a single safe path segment using the existing
`rustic_git_storage::store::valid_segment` (already rejects `.`, `..`, `/`, and
anything outside `[A-Za-z0-9._-]`). Enforce at the API trust boundary in `create_env`,
and defensively again in `mkdir_env_mounts` and `render`. Validate `path` as an
absolute, colon-free path.

## 2. High — scheduling and data integrity (workspaces)

### H1. Any agent can lease a job the scheduler deliberately left unassigned
`bins/server/src/vol_agent.rs:396` — `j.agent.as_deref().is_none_or(|a| a == q.agent)`
means a job with `agent: None` goes to whichever agent polls first. But `None` is not
"unscheduled yet": the scheduler leaves it `None` when the owner's bound agent is dead
(`scheduler.rs:388`), and the requeue sweep clears it on every expiry (`lease.rs:31`).
So work whose subvolumes live on node A gets executed on node B — a push snapshots a
nonexistent subvolume (workspace marked Error), a clone materializes on the wrong node
and splits the owner's data across pools. This defeats the entire owner-binding design.
**Fix:** only lease jobs where `j.agent == Some(q.agent)`.

### H2. Fixed 120s lease with no renewal and no shell-out timeouts ⇒ routine double execution
`vol_agent.rs:400`. Jobs shell out to `docker run` (image pull), `btrfs send` of
multi-GB deltas, and Azure uploads — minutes, easily. No heartbeat renews the lease, no
`Command` in `ops.rs`/`compose.rs`/`container.rs` has a timeout. The sweep requeues a
still-running job, the binding sends it back to the same agent, and it now runs
concurrently with itself. Non-idempotent replays then fail: `create_subvol` on an
existing `live` errors (`ops.rs:166`), clone into an existing path errors
(`ops.rs:624`) — three such "failures" mark a healthy workspace `Error`.
**Fix:** per-job lease renewal heartbeat, make create/clone tolerate an existing `live`,
add timeouts to shell-outs.

### H3. Environment re-materialization is dead code — and its one call site is wrong
Nothing in production ever writes `Workspace.volume`/`Environment.volume` (only a test
fixture does), despite `model.rs:86` claiming the job-done handler does. So `EnvUp`'s
recovery branch (`bins/agent/src/lib.rs:514`) can never fire: an environment whose local
subvolume is gone (pool wipe, node replacement) is silently rebuilt **empty** even
though its pushed history exists in the registry — the user's data looks lost. When
someone wires the pointer up, the call `engine.pull_env(&env.id, r)` at `lib.rs:516` is
also argument-swapped against `pull_env(owner, id)`.
**Fix:** set `volume` in `job_done` on first successful push, fix the call, or drop the
pointer and key recovery on "registry history non-empty".

### H4. Stale completion reports corrupt job state
`vol_agent.rs` `job_done`/`job_failed` overwrite state unconditionally, with no check of
lease ownership or current state. After a lease expiry and requeue: attempt 2 succeeds
(`Done`), attempt 1's late failure flips the job back to `Queued` → a **third** run of,
e.g., `WsDelete` or `EnvDown`. Conversely a late `done` marks a requeued job `Done`
when nobody ran it. **Fix:** no-op unless `state == Leased && agent == reporter`.

### H5. Deleted workspace resurrected to Ready by an in-flight job
`mark_env_state` explicitly refuses to overwrite `Deleted` ("delete wins");
`mark_ws_ready` (`vol_agent.rs:433`) has no such guard. Delete a workspace while its
create/clone job is leased and the doc flips back to `Ready` with no volume behind it,
reappearing in listings as live. **Fix:** mirror the env guard.

### H6. Two paths that can destroy the only copy of unpushed data
- `engine/pool.rs:98` — `set_lineage` is `fs::write(...).unwrap()`: truncate-then-write
  with no tmp+rename. A crash mid-write leaves an empty `.lineage`, losing the `unpushed`
  marks that are the only record staged data exists; the next janitor tick then deletes
  those blobs as unreferenced. The `unwrap` also panics the agent on ENOSPC.
- `bins/agent/src/lib.rs:240` — the janitor computes its keep-set without taking
  `ws_lock`, so a tick landing between the staged-blob write (`ops.rs:206`) and the
  lineage append (`ops.rs:230`) sweeps a freshly staged file, and the retried push then
  fails forever on the missing stage file.

**Fix:** tmp+rename and return `Result`; have the sweep skip files younger than an hour
or take the lock.

### H7. Sweep-exhausted jobs never mark the doc Error
`lease.rs:33` sets `JobState::Failed` but never calls `mark_ws_error` (that only runs on
the HTTP `job_failed` path). A dead agent's `WsCreate` leaves the workspace in
`Creating` forever — a permanent UI spinner with no error.

## 3. High — performance

Ranked by impact. These are throughput/cost issues, not correctness.

| # | Finding | Location |
|---|---|---|
| P1 | Chunked blob upload is O(N·K): each PATCH re-streams the whole partial layer. A 10 GiB layer in 100 MiB chunks moves ~1 TiB each way. Completion re-reads it all again to hash. | `registry/src/uploads.rs:280,434` |
| P2 | No SlateDB object-store or block cache configured at all — every SST block miss is an S3 GET, under every tag read, visibility check and ref read. Biggest single metadata-latency lever. | `storage/src/pool/mod.rs:143` |
| P3 | `reachable_set` enumerates every object in the repo on every incremental fetch. A `have` is always a commit, so the full closure isn't needed — O(objects) → O(commits). | `git/protocol/upload/mod.rs:183` |
| P4 | One base-branch push triggers up to 25 full network fetches (one per diverged PR), serially, under the repo's merge lock. One union fetch would do. | `pulls/src/merge_worker.rs:629` |
| P5 | Agent long-poll costs ~90 Cosmos ops per agent per 30s at idle, including a heartbeat *write* per second and a fetch-all-agents to find one. | `vol_agent.rs:385` |
| P6 | The requeue sweep runs on **every replica** unguarded — N−1 pods do wasted CAS-racing work. One-line `is_leader()` fix. | `vol_agent.rs:603` |
| P7 | Agent 204 branch has no sleep floor — safe only because the server holds the poll 30s; any proxy with a short idle timeout turns it into a busy-spin. One-line fix. | `bins/agent/src/lib.rs:185` |

P6 and P7 are one-line changes with near-zero diff; P2 is config only. Do those three first.

Medium performance items worth scheduling: receive-pack walks the closure once per
pushed ref (`receive.rs:263`); rejected pushes upload the whole pack to S3 *before*
validating it (`receive.rs:228`); `repack` writes the pack twice and never re-deltas, so
it consolidates file count but never shrinks the repo (`git/src/gc.rs:155`);
`manifest_stat` does a full prefix LIST per manifest push (`manifests.rs:210`);
`grant_renew` holds the global leader lock across N serial store ops (`app/src/lib.rs:589`);
the janitor is O(V²) and blocks the reactor (`agent/lib.rs:228`); four serial per-team
point reads in the workspaces API that should be `join_all` (`api.rs:499,581,764,784`).

## 4. Medium — correctness and resource leaks

**Merge subsystem** (`crates/pulls`):
- A lease lapse can record an actually-landed merge as **Failed/Refused**: both workers
  compute the same merge, A's push wins, B's `force-with-lease` fails and B records
  refused — so the PR shows failed despite having merged, and `HeadMoved`/`PullMerged`
  never fire. Fix: on push failure, re-check `is-ancestor` before recording refused.
  (`merge_worker.rs:499`)
- The rebase arm doesn't pin `GIT_COMMITTER_DATE`, so rebased commit ids are
  non-deterministic — contradicting the module's own retry-determinism claim.
  (`merge_worker.rs:595`)
- `claim_merge` (scan variant) omits the `state == Open` guard its sibling has. It has no
  callers — delete it. (`pulls/jobs.rs:51`)

**Registry / storage:**
- `manifest_cache.lock().unwrap()` on every manifest GET/PUT/DELETE — one panic while
  held cascades all subsequent manifest requests into 500s. Use the poison-tolerant form
  `storage/src/auth.rs` already uses. (`manifests.rs:179`)
- A legitimate manifest with an annotation keyed `digest` holding a non-digest string is
  rejected on push, because the blob-collection walk errors instead of filtering.
  (`manifests.rs:133`)
- `now_ms()` `.expect("system clock before 1970")` sits on the claim/renew request path.
  (`ownership/mod.rs:29`)

**Workspaces resource leaks:**
- `EnvDelete` never removes `{pool}/env/{id}` — every deleted environment leaves its
  compose dir behind forever. *(Observed live: two orphan dirs on the production VM.)*
  It's also non-idempotent: `compose::down` requires the file to exist, so a retry after a
  partial delete fails and exhausts. (`agent/lib.rs:628`)
- Squash and block-restore never delete `{pool}/img/{blob}.img`, and the janitor never
  sweeps `img/` — unbounded pool growth. (`ops.rs:820`)
- A stale `{id}.squashing` latch permanently disables auto-squash for that volume; chains
  then grow past `chain_max`. (`ops.rs:328`)
- A restarted agent whose persisted id no longer exists server-side loops on 404 forever
  instead of re-registering. (`agent/lib.rs:111`)
- Job docs, commit history and lineage grow without bound; no pagination on history or
  any list route; `queued_jobs` drains all pages every second per agent.

**Workspaces API validation:**
- `create_ws` accepts any `region` string; a typo means the job is never scheduled and the
  workspace sits in `creating` with no error, forever.
- `name` is unvalidated (empty, huge, control chars); `quota_gb` is accepted and stored
  but enforced nowhere — no btrfs qgroup — so a "5 GB" workspace can fill the pool.
- Team-owned environment history/refs always return empty, because `volume_history` reads
  `get_history(caller_username, ...)` while the commits were pushed under the team's
  namespace. (`api.rs:809`)

**Security (acknowledged ceiling, worth promoting):** vol-agent tokens are fleet-wide,
not region-scoped (`vol_agent.rs:10`) — a leaked agent token from one region can rewrite
any volume's commit history and move any `main` ref fleet-wide. It's an existing
`ponytail:` note, but it's a security boundary rather than a convenience shortcut.

## 5. Web app and code quality

The Next.js app came out clean on the things that matter most:

- **Auth is well built.** The API bearer token is deliberately kept out of the session
  object and read back server-side from the encrypted JWT, so `/api/auth/session` never
  exposes it to client script. The passkey provider correctly defends the public callback
  URL with a 60-second HMAC and `timingSafeEqual`.
- **No XSS found.** The only `dangerouslySetInnerHTML` is shiki output with an allowlisted
  grammar; the README renderer emits JSX text nodes, never raw HTML.
- Findings are minor: `secureCookies` silently downgrades if `AUTH_URL` is unset;
  server actions should validate `owner`/`repo` slugs before feeding them to
  `revalidatePath`; `destroyRepo`'s confirm string should be `owner/repo`; only one
  `loading.tsx` exists in the entire app, so most navigations freeze on the old page.

Rust-side quality notes:
- **Structured logging is the biggest debt in aggregate**: ~70 of the ~219 `ponytail:`
  markers are `eprintln` placeholders across five crates. One `tracing` adoption retires
  all of them in a single mechanical PR, and ops stops grepping prose.
- Errors are `Box<dyn Error>` workspace-wide, so several call sites branch on message
  *substrings* (`"BUSYGROUP"` in `cache/disk.rs:64`, routing prose in `boot.rs:511`, and
  three tests). Introduce typed errors only at the seams that branch.
- **Missing test for a named invariant:** the `local()`/`networked()` secret-redaction
  split in `merge_worker.rs` is what CLAUDE.md says keeps the peer secret out of error
  messages, but nothing asserts it. One test against a dead port would freeze it.
- `serde_yaml` is archived/unmaintained (RUSTSEC-2024-0320) — swap for `serde_yml`.
- No `cargo audit`/`cargo deny` in CI, despite a large crypto surface (JWT, ssh, pgp,
  registry auth).
- CLAUDE.md's workspace-layout line is stale: it omits `crates/workspaces` and
  `bins/agent`, and says "three binaries" where four are built.

## 6. What the auditors found solid

Worth recording, since it's what the fixes above must not break:

- **Ownership routing genuinely holds.** The pre-auth middleware refuses every path it
  cannot route rather than falling through to a handler that would open a DB, and
  `every_browse_route_is_routable` scrapes the router source to assert it — the test that
  would have caught the historical `imagetags` bug.
- **Registry invariants all verified:** only client-DELETE and the GC sweep delete blobs;
  the sweep aborts (never continues) on an unreadable manifest; manifests stored and
  returned verbatim; every path→key conversion goes through a validated `Digest`.
- **Merge idempotency is real:** deterministic commit ids, `is-ancestor` and
  tree-equality retry guards, `force-with-lease` against the oid the merge was computed
  from, and no argv carrying the peer secret is ever formatted into an error.
- **Pool concurrency is careful:** `OnceCell` single-flights opens, `evict_if_same` keys
  on the exact `Arc` pointer, and no lock is held across an await anywhere in
  pool/store/cache.
- **The staged-push crash-recovery seam** and the cross-volume sharing guards
  (`other_unpushed_blobs`, `other_lineage_snap_names`) correctly close the
  delete-source-strips-clone's-parent class of bug.
- Packs stream on both fetch and push; blob sizes are read from object headers rather than
  by inflating; auth is cached with bounded hit+miss; zero `TODO`/`FIXME` in the tree, with
  debt tracked as structured `ponytail:` markers instead.

## Suggested order of work

1. **C1** — mount path validation. One function call, closes a root-level host escape.
2. **H1, H4, H5** — three small guards in `vol_agent.rs` (lease only assigned jobs; check
   lease ownership on report; don't resurrect deleted workspaces).
3. **P6, P7** — two one-line fixes (leader guard on the sweep, sleep floor on the agent poll).
4. **H6** — tmp+rename for lineage writes; janitor age floor. Protects unpushed data.
5. **H2** — lease renewal plus idempotent create/clone replay.
6. **H3, H7** — env re-materialization pointer; sweep marks docs Error.
7. **P2** — configure the SlateDB caches (config only, large latency win).
8. Medium leaks: `EnvDelete` dir cleanup, `img/` sweep, stale squash latch, agent re-register.
9. `tracing` adoption (retires ~70 markers); `cargo deny` in CI; `serde_yaml` swap.
10. **P1, P4** — the two large refactors (multipart upload sidecar, single union fetch).
