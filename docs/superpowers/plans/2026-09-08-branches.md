# Branches Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Branches tab that lists a repo's branches and deletes one, refused for the default, a protected, or an open-PR head branch.

**Architecture:** One new peer-only server route that deletes through `update_refs` (so every existing rule applies), one api-tier route that gates the caller and the open-PR case and forwards, one web page over the refs the browse proxy already serves, two probe ids.

**Tech Stack:** Rust (axum, gix), Next.js app router, the SLO probe.

**Spec:** `docs/superpowers/specs/2026-09-08-branches-design.md`

## Global Constraints

- Every ref write goes through `kloudlite_gitbase::refs::update_refs` — never `update_refs_txn` directly, never a bare key delete.
- The default branch is `refs::DEFAULT_BRANCH` (`main`); refused with 409 at the api tier and at the server.
- Delete is a compare-and-swap on the oid the client sent: `RefUpdate { name: "refs/heads/<branch>", old: Some(oid), new: None }`.
- A new browse route must be added to `BROWSE_TAILS` in `bins/server/src/router/route.rs`.
- Caller gate at the api tier: `settings_caller` (may act under the owner). The server route trusts the owner header like `protect` does.
- Error sentences shown verbatim: 409 protection sentence from `update_refs`; "the branch moved; reload"; "close or merge pull request #N first"; "the default branch cannot be deleted".
- House style: comments say why; commit subjects imperative sentence case; no new dependencies.
- All four tasks touch disjoint files; Tasks 1, 2 and 3 may run in parallel worktrees; Task 4 after 1 and 2 (it exercises them on the fleet).
