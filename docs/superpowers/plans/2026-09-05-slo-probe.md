# SLO Probe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `kloudlite-git-slo` CronJob walks a synthetic user's journey every five minutes, reports live to the admin process, and the superadmin console shows runs, budgets and burn.

**Architecture:** Catalogue in Rust held equal to `deploy/slo.md`; probe binary reports `RunReport`s to `PUT /admin/slo/runs/{id}` after every stage; the admin process (only `kloudlite.*` writer) stores runs and results in ClickHouse, serves the read model, evaluates `SloBurn`/`SloProbeMissing` in the existing evaluator, and posts a webhook line on failure; the web adds area nine.

**Tech Stack:** Rust (axum, kloudlite_git_core::{jwt,httpx,log,metrics}, kube), ClickHouse SQL over HTTP (`history::History::post`), Next.js app router, Kubernetes CronJob.

**Spec:** `docs/superpowers/specs/2026-09-05-slo-probe-design.md`

## Global Constraints

- The admin process is the ONLY writer of `kloudlite.*`; the probe never talks to ClickHouse.
- Every `kloudlite.*` reader queries `FINAL`; `ts` derives from the probe's step, never `now()` at insert.
- Every caller-shaped value in SQL goes through `history::series::ident` or is checked against `CATALOGUE` first.
- Logs follow `docs/superpowers/reviews/logging-events.md`: `subject.verb[.qualifier]`, fixed field names; every metric registered at boot via `kloudlite_git_core::metrics::register`.
- No `std::env::var` for a knob that has a `Settings` field; the probe's own env is read once in `Config::from_env`.
- Rust pods: uid 1001, read-only root; anything written goes to a mounted `/tmp`.
- CI gate: `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test`, `cd web && bun run lint typecheck test build`.
- Commit subjects imperative sentence case, no tool attribution. Comments explain why.
- Skipped step = no sample. A step's failure never aborts the run; only unusable state skips dependents. Teardown always runs.
- The probe deletes only objects whose name starts with `run-{id}` or the three named drill objects.
