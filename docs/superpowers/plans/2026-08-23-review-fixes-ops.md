### Task 1: Run the Rust image as a non-root user

**Files:**
- Modify: `Dockerfile:28-43` (final stage)

**Interfaces:**
- Produces: uid/gid `1001`, user `rustic`, owning `/var/cache/rustic-git` and `/var/lib/rustic-git`. Task 2's `runAsUser/runAsGroup/fsGroup: 1001` must match this uid.

**Context:** The final stage has no `USER`, so every Rust process in the cluster runs as root with all capabilities (spec §0 #9). The two directories the binaries write are `RUSTIC_GIT_CACHE_DIR=/var/cache/rustic-git` (pack cache; an `emptyDir` in the cluster, a bare directory in a local `docker run`) and the parent of `RUSTIC_GIT_HOST_KEY=/var/lib/rustic-git/host_key` (generated by `ssh-keygen` on first start when no key is mounted — the cluster mounts one at `/etc/rustic-git` instead, read-only). Both must exist and be owned by the runtime user, or a local run fails on first write. uid 1001 mirrors `web/Dockerfile:33` so the two images share one convention.

- [ ] **Step 1: Add the user and own the writable directories**

Replace `Dockerfile:28-43` (from `FROM debian:bookworm-slim` to the end) with:

```dockerfile
FROM debian:bookworm-slim
# openssh-client: the server shells out to ssh-keygen to generate its host key on first start
RUN apt-get update && apt-get install -y --no-install-recommends ca-certificates openssh-client \
    && rm -rf /var/lib/apt/lists/*
# All three binaries. One image, three processes: the git server, the api server
# and the merge worker are built from the same source and deployed separately, so
# a shared image keeps them on the same commit without coupling their lifecycles.
# Each Deployment picks its process with `command`, so a binary missing here is a
# CrashLoopBackOff there, not a build error.
COPY --from=build /src/target/release/rustic-git /usr/local/bin/rustic-git
COPY --from=build /src/target/release/rustic-git-api /usr/local/bin/rustic-git-api
COPY --from=build /src/target/release/rustic-git-worker /usr/local/bin/rustic-git-worker
# Not root. Nothing here needs a capability: the listeners bind 8080/2222/8081/8082, the host
# key lives in a mounted Secret in the cluster, and the pack cache is a directory. The two
# directories the binaries write are created and owned here so a plain `docker run` (no
# mounts) works; in the cluster both are mounts and `fsGroup` on the pod makes them writable.
# uid 1001 matches web/Dockerfile so one securityContext convention serves both images.
RUN useradd --system --uid 1001 --no-create-home --shell /usr/sbin/nologin rustic \
    && mkdir -p /var/cache/rustic-git /var/lib/rustic-git \
    && chown rustic:rustic /var/cache/rustic-git /var/lib/rustic-git
ENV RUSTIC_GIT_CACHE_DIR=/var/cache/rustic-git RUSTIC_GIT_HOST_KEY=/var/lib/rustic-git/host_key
USER rustic
EXPOSE 8080 2222
ENTRYPOINT ["rustic-git"]
CMD ["serve"]
```

Run (needs a docker daemon; a cold build compiles the dependency layer, ~10+ minutes the first time):

### Task 2: Harden the four Rust workloads with a securityContext

**Files:**
- Modify: `deploy/rustic-git.yaml` — leader pod spec (`:40-51`, `:204-209`, `:214-217`), srv pod spec (`:257-268`, `:412-417`, `:422-425`), api (`:529-531`, `:575-577`), worker (`:619-621`, `:655-663`)

**Interfaces:**
- Consumes: uid `1001` from Task 1.

**Context:** `rustic-git-web.yaml:105-108` is the container-level pattern already in the cluster (`allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, `capabilities: drop ALL`). Two things the Rust pods need on top of it: `runAsNonRoot` (so the kubelet refuses an image that forgot `USER`), and `fsGroup` — because the host key is a Secret mounted `defaultMode: 0400`, owned by root, which a non-root process cannot read. With `fsGroup` set, the kubelet chowns volume files to group `1001`; the mode must then grant the group read, so `0400` becomes `0440`. `emptyDir`s under `fsGroup` are group-writable, which is what the cache needs. The api tier has no cache volume today but `RUSTIC_GIT_CACHE_DIR` points at `/var/cache/rustic-git` from the image `ENV`; with a read-only root that directory must be a mount, so the api gets a small `emptyDir` too.

### Task 4: Narrow the registry ingress to `/v2` and redirect it to HTTPS

**Files:**
- Modify: `deploy/rustic-git.yaml:715-750` (the `rustic-git-registry` Ingress)

**Interfaces:**
- Consumes: the `rustic-git-http` ClusterIP Service from Task 5. **Apply Task 5's yaml first, or in the same `kubectl apply`** — this Ingress will point at it.

**Context:** The registry host routes `/` (the whole git surface) to the fleet with `ssl-redirect: "false"`, justified by a comment about Cloudflare Flexible mode — but the host comment nine lines above says `cr.khost.dev` is DNS-only and TLS is terminated here by cert-manager. There is no proxy to loop, so the redirect is safe, and without it Basic credentials are accepted over plain HTTP. The registry owns `/v2/...` (including `/v2/token`); nothing else on this host is meant to be reachable.

- [ ] **Step 1: Edit the Ingress**

Replace the annotation comment + value at `:722-725` and the `paths:` block at `:743-750`:

```yaml
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt
    # Redirect to HTTPS: this host is DNS-only (see above), so the origin IS the TLS endpoint and
    # there is no proxy to loop. `docker login` sends Basic credentials; over plain HTTP they are
    # readable on the wire. The app's ingress is the opposite case (Cloudflare Flexible fetches
    # the origin over HTTP) — do not copy this value there.
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    # A layer is one request. The default 1m ceiling turns any real image into a 413.
    nginx.ingress.kubernetes.io/proxy-body-size: "0"
    # A large layer takes longer than 60s to receive.
    nginx.ingress.kubernetes.io/proxy-read-timeout: "600"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "600"
    # Buffering a layer in nginx before passing it on doubles the disk it touches and
    # delays the first byte the registry sees.
    nginx.ingress.kubernetes.io/proxy-request-buffering: "off"
spec:
  ingressClassName: nginx
  tls:
    - hosts: [cr.khost.dev]
      secretName: rustic-git-registry-tls
  rules:
    - host: cr.khost.dev
      http:
        paths:
          # Only the registry: `/v2/` and everything a client follows from it (`/v2/token`, blob
          # and manifest paths) live under this prefix. The git smart-HTTP surface and /healthz
          # have no business on this hostname; they stay on the app's ingress.
          - path: /v2
            pathType: Prefix
            backend:
              service:
                name: rustic-git-http
                port:
                  number: 80
```

Also update the block comment at `:701-707`: replace the sentence "A registry client owns the whole host: it asks for `/v2/` and follows `Location` headers the server writes, so sharing a host with an app means every one of those paths has to be carved out of the app's namespace and kept carved." with "A registry client asks for `/v2/` and follows `Location` headers the server writes — all under `/v2/`, which is why that one prefix is the whole rule below.
