# Audit remediation + k3s migration — roadmap

**Superseded in part on 2026-08-26.** The container-runtime direction changed: rather than
driving a container daemon directly, workspace/environment orchestration moves to **k3s**, and
the per-node agent becomes a **node-level Kubernetes controller**. Plans below are re-scoped
accordingly.

- **Audit:** `docs/superpowers/audit-2026-08-25.md` (consolidated), `-raw.md` (verbatim)
- **k3s architecture:** `docs/superpowers/specs/2026-08-26-k3s-architecture-design.md`
- **Cancelled spec:** `specs/2026-08-25-direct-container-runtime-design.md` (bollard/compose
  replacement — kept for the reasoning, not to be implemented)

## What the k3s decision deleted

The migration removes the machinery several audit findings live in. Fixing them first would be
fixing code that is about to be deleted:

| Audit finding | Fate |
|---|---|
| H1 — unassigned jobs leased by any agent | **Gone**: the controller watches `spec.nodeName`; there is no lease to hand out |
| H4 — reports overwrite job state | **Gone**: no job docs; status flows through the `/status` subresource |
| H5 — deleted workspace resurrected | **Gone**: reconcile is driven by the object's own spec |
| H7 — sweep never marks the doc Error | **Gone**: no sweep; status conditions replace it |
| H2 — 120s lease, no renewal | **Half gone**: the lease disappears; the "make replay idempotent" half is still real work |
| P5, P6 — Cosmos poll cost, sweep on every replica | **Gone**: watches replace polling |
| M1 — EnvDelete leaks the compose dir | **Gone**: no compose files |
| C1 — mount path traversal | **Still real** — mounts remain, as pod volumes |

Also cancelled: the hand-rolled IPAM allocator, per-environment bridge networks, the
VXLAN/WireGuard overlay work, and the one-environment-per-workspace attachment limit. flannel,
CoreDNS and NetworkPolicy replace all of it.

## Phase 1: stop at Task 4

Tasks 1–4 are committed on branch `audit-phase1`:

- `validate_mount` — the single rule for a mount folder and path
- refusal at the environment API boundary
- refusal again in the renderer and the root agent
- lease only jobs addressed to the polling agent

**Tasks 5–8 are superseded.** They fix `job_done`/`job_failed`, `mark_ws_ready`, the requeue
sweep and the agent's poll loop — every one of which the k3s migration deletes. There is also no
live exposure: the agent VM that ran them is gone.

`validate_mount` survives the migration and should be reused when mounts become pod volumes.

## Order from here

1. **Provision the cluster** (Plan 2A) — blocked on the sizing decision and quota.
2. **Write Plan 2B** — the Rust migration: CRDs, the node controller, deleting the job system.
3. **Phase 6**, which is entirely independent of the migration and has the merge bug with
   user-visible wrong state.
4. **Phase 3's surviving half** (H6 data-loss paths) and **Phase 4** — both in the btrfs engine,
   which the migration does not touch.
5. **Phase 5's git/registry half.**
